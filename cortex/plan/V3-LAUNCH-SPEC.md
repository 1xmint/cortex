## Deliverables (one PR)

1. **Migration v61**: `verification_runs` + `verification_checks` exactly per VERIFIER.md:216–237, plus indexes on `verification_runs(run_id, step_id)` and `verification_checks(verification_id)`. Also add whatever column/table you choose for frozen check specs (below) in the same migration. Copy migrate_v52's shape.
2. **Freeze the specs**: at the scheduler.rs:654 seam, persist the derived `Vec<CheckSpec>` (serde JSON) retrievable by (run_id, step_id) at verification time. Keep the existing RequiredCheck display path for the worker unchanged. Derivation stays at dispatch time (before the worker sees the task — VERIFIER.md contract-freeze rule).
3. **db.rs accessors**: `claim_verification(run_id, step_id, attempt, tree_hash, runner_image) -> Option<String>` (INSERT ON CONFLICT DO NOTHING against UNIQUE(run_id,step_id,attempt) — this is the CAS; None = already claimed), `record_check_execution(...)`, `finish_verification(verification_id, verdict)`, `get_receipt(run_id, step_id) -> Option<Receipt>`, and **`refund_credits(clerk_user_id, amount, description, idempotency_key)`** — append-only POSITIVE `credit_transactions` row, reason `task_failed_refund`, same idempotency/bucket mechanics as #437's `deduct_credits` (mirror the charge's bucket split so a refund restores what the charge drew).
4. **Verification driver** (new `crates/api/src/verification_driver.rs`): load frozen specs → `claim_verification` → snapshot the delivered tree at head_commit into a temp dir via `git worktree add --detach` (NEVER the worker's working directory — VERIFIER.md "clean tree at the delivered commit") → run each spec through `ContainerCheckRunner` → `record_check_execution` per check → `verify_from_executions` → `finish_verification` → billing: derive `BillingState` by querying the ledger for `charge_key`/`refund_key` rows, call `billing_effect`, apply Charge via `deduct_credits(charge_key(vid))` / Refund via `refund_credits(refund_key(vid))`. INCONCLUSIVE: up to 2 bounded retries, then `tracing::error!` operator alert, no ledger writes ever. Worker-reported failure (exit_code != 0) short-circuits to FAILED without container time.
   - **Charge amount**: find where a run's quoted credit price lives (`routes::estimate_run` exists; #437 adds metering primitives). Use the quoted amount; if no quoted amount is reachable for a step, record the verdict and skip the ledger write with a `tracing::warn!` — never invent a price (pricing is Josh-owned). Document which path fires in the PR body.
   - **No double-charge**: map existing `deduct_credits`/raw-insert callers first; if a legacy charge path covers the same run, verdict-billing must be the only charger for verified steps — reconcile and document.
5. **Trigger**: in ws.rs after delivery facts are known, `tokio::spawn` the driver (don't block the completion handler; step state machine untouched). Stale-lease deliveries (complete_step CAS false) must NOT bill — check the CAS result before/while claiming.
6. **Receipt endpoint**: `GET /api/runs/{run_id}/steps/{step_id}/receipt` → the Receipt.tsx:37 JSON shape, 404 when no verification exists, ownership-scoped by user like get_verifier_report. Add to BOTH router blocks in lib.rs.
7. **Tests**: fresh-DB migration reaches v61 with both tables; double-claim returns None the second time; refund replay with same key is a no-op; INCONCLUSIVE produces zero ledger rows; driver sequence with a mock `CheckRunner` (generic — RPITIT) covering Verified→Charge, Failed-after-charge→Refund, duplicate-execution worst-of; receipt endpoint shape (serde round-trip matching the TS field names exactly).
