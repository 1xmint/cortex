## 0. How to read this

Each task carries a **recommended effort level**. The rule behind the assignments:

| Effort | Use for | Why |
|---|---|---|
| **Opus 5 · xhigh** | Irreversible architecture decisions, schema design, security boundaries, pricing-unit design | Wrong answer costs weeks. Buy the judgment. |
| **Opus 5 · high** | Non-obvious implementation, router policy, verifier design, anything touching money | Default for real engineering. |
| **Sonnet 5 · medium** | Spec-complete implementation, CI YAML, test writing, refactors with a clear target | The spec carries the difficulty; the model just executes. |
| **Sonnet 5 · low** | Mechanical edits, renames, dependency bumps, doc formatting | Judgment already spent. |

Two standing rules, both earned from what this audit found:

1. **Nothing grades its own homework.** `VISION.md` self-reported thirteen systems as "WORKING". Independent checks contradicted several. Status claims must come from a check, not an assessment.
2. **A gate that cannot fail is not a gate.** This repo has three required CI checks; two of them are structurally incapable of failing. Same disease as a verifier that always says PASS.

## 2. Three contradictions to resolve before writing code

### 2.1 The business model in the repo is the opposite of the intended one

`VISION.md:17` — *"$6.99/mo unlimited BYOK platform. Users bring their own API keys"* and `:457` — *"no markup on AI usage."*

Intent: Cortex holds operator-funded keys; users buy credits.

These are not adjustable versions of each other. They imply different auth, different billing, different threat model, different infrastructure. **`VISION.md` must be rewritten or retired before it misleads another build session** — it currently outranks everything as declared "single source of truth."

**Effort: Opus 5 · xhigh.** This decides pricing, ToS posture, and infra spend.

### 2.2 The architecture spec assumes the model you are leaving

`docs/ARCHITECTURE.md` is genuinely strong work — DAG orchestration with typed edges, lease/CAS state machine, dynamic heal insertion, per-attempt git worktree isolation, an evaluator/policy split with exact scoring constants, a failure taxonomy with a routing-impact matrix. Most of it is worth keeping.

But its stated core principle (§ "Core Principle") is *"Brain owns decisions… Workers own local execution and **user-provider access**."* It assumes workers run `claude`/`codex` **on the user's machine with the user's auth**:

- `WorkerFailureKind`: `CliNotFound`, `CliNotAuthenticated`, `CliAuthExpired`
- `provider_capabilities` is keyed by `worker_id`
- § 9 has workers creating git worktrees on their own filesystem

Server-held keys **invert that principle**. Consequences:

| Spec element | Survives? |
|---|---|
| DAG + `step_dependencies` edge types | ✅ Keep as-is |
| Lease / CAS / restart recovery | ✅ Keep as-is |
| Heal insertion, context budgeting, typed step outputs | ✅ Keep as-is |
| Evaluator/policy split | ✅ Keep the shape, re-derive the constants |
| CLI failure taxonomy | ❌ Becomes HTTP status + provider error codes |
| Per-worker `provider_capabilities` | ❌ Becomes a central key pool with per-tenant quota |
| Worktrees on the user's machine | ⚠️ Moves onto **your** infrastructure — new cost and a new security boundary |

**Effort: Opus 5 · xhigh.** Amend `ARCHITECTURE.md` in place, section by section. Do not start a new doc; this one is too good to abandon.

### 2.3 The core product claim is not supported by evidence

Vision: *"becoming the best at everything"* by routing across providers.

What the 2026 literature actually shows:

- **TwinRouterBench** (arXiv 2605.18859), 100 held-out SWE-bench cases: best router 75/100 vs **unrouted Opus 4.6 at 74/100**, at 53% lower spend. At n=100, p≈0.75, binomial SE is ±4.3pp — **a 1-point difference is noise.** The robust result is *parity at half cost*.
- **LLMRouterBench** (arXiv 2601.07206): *"several recent routing methods, even including the commercial router OpenRouter, do not outperform a simple baseline"* — **OpenRouter measured at −24.7% vs best single model.** On queries only 1–3 models get right, top routers score ~24%. Routers are weakest exactly where routing would matter most.
- **TwinRouterBench**, again: a *badly calibrated* rule-based router cost **$172.56 vs $54.73 for just using Opus** — 3x worse than no router.

**A router that beats frontier on coding is not a defensible claim. A router that matches frontier at ~half the cost is well-supported.**

The lever that consistently does work is **verification**: best-of-N plus an *execution-based* verifier. Without a real verifier, parallel sampling gives diminishing returns because you cannot identify the winner.

> **Reframe:** Cortex does not sell "smarter routing." It sells **a verified engineering outcome at half the frontier bill** — and can prove the tests ran. Routing is the cost mechanism; verification is the product.

**Effort: Opus 5 · xhigh** (positioning + pricing unit). This is the highest-leverage decision in the document.

## 3. The constraint that shapes the product: provider terms

Verified verbatim from Anthropic's Commercial Terms (effective 2025-06-17):

- **§D.4** — *"Customer may not and must not attempt to (a) access the Services to build a competing product or service, including to train competing AI models **or resell the Services except as expressly approved by Anthropic**"*
- **§A.1** — *"Anthropic gives Customer permission to use the Services, **including to power products and services Customer makes available to its own customers and end users**"*

These two clauses draw a real line, and it runs straight through the credit model:

| Design | Reading | Risk |
|---|---|---|
| Credit = "1M Opus tokens" | Selling metered access → **resale** | ❌ High |
| Credit = "one verified task / merged PR" | A product that uses the API → **§A.1** | ✅ Defensible |

**This is not a legal footnote — it is a schema decision.** It determines what a credit is denominated in, which determines the `credit_transactions` table, the pricing page, and the metering code. Getting it right costs nothing today and is very expensive to retrofit.

Also relevant, and verified: Anthropic's February 2026 terms update banned using **subscription OAuth tokens** (Free/Pro/Max) in third-party tools, with enforcement from 2026-04-04. **Operator-funded API keys are explicitly the compliant path** — so the pivot is *more* compliant than what `VISION.md` describes, where `:206-207` already flags the current OAuth flow as *"prohibited."* Note that a provider broke an entire product category with ~6 weeks' notice; multi-provider is genuine risk management, not just a feature.

**Actions**
- Denominate credits in verified outcomes, not tokens. **Opus 5 · xhigh**
- Request written clarification from Anthropic (§D.4 says approval is available). **Human — Josh, not an agent**
- Have counsel read OpenAI / Google / xAI terms directly; automated fetch was blocked (403) so those readings are secondhand. **Human**
- Cap any single provider at ~40% of routed volume. **Sonnet 5 · medium**

## 4. Margin reality

Verified: **per-token markup on gateways has gone to zero.** OpenRouter takes 5.5% on *credit purchase*, not tokens; Vercel AI Gateway is zero-markup including BYOK; Cloudflare charges 5% on credit purchases. Competing bundles: **OpenCode Go $10/mo** (Grok 4.5, GLM-5.2, Kimi K3, MiniMax M3) and **GLM Coding Plan $18/mo**.

**You cannot build a margin on routing tokens.** That business is already commoditized.

Where margin can actually come from:

| Lever | Contribution | Durable? |
|---|---|---|
| Prompt caching (cache reads at 0.1× input) | Large — agent loops resend history constantly | Yes, but competitors have it too |
| Routing to a cheaper tier | ~50%, well-evidenced | Yes — the core mechanic |
| Batch API 50% | ~0 for interactive coding | No |
| Credit breakage | Small, and carries unclaimed-property exposure | Handle carefully |

Realistic: **~45–55% gross margin before infra; 35–45% after** sandboxes, Postgres, observability, and payment processing. That is a real business, not a SaaS-margin business, and it compresses as model prices fall.

One free win worth designing for: on most Claude models **cache reads do not count toward ITPM**, so aggressive caching raises effective throughput as well as cutting cost.

⚠️ **Rate limits will cap you before revenue does.** Anthropic monthly spend caps: Start **$500**, Build **$1,000**, Scale **$200,000**. A $1,000/mo cap supports roughly 4–8 active customers. Acceleration limits also throw 429s on sharp usage increases — a good launch day looks exactly like abuse. **Start the tier-increase conversation before you have customers.** **Human — Josh**

## 6. Tech decisions

| Layer | Choice | Why |
|---|---|---|
| Orchestration | **Temporal** | Runs are long, multi-provider, must survive redeploy, and must be exactly-once on billing. Restate is the credible Rust-native alternative; Temporal's tenant isolation wins when metering money. **Do not hand-roll.** |
| Datastore | **Postgres (Neon)** | SQLite is single-writer, unsafe multi-node, and cannot give `SELECT FOR UPDATE` on a credit ledger. Neon adds branch-per-PR databases — high leverage for an agent product. |
| Billing | **Stripe + Metronome** (Stripe completed the acquisition 2026-01-13) or self-hosted **Lago** | Proven prepaid drawdown at AI-lab scale. Avoid Orb for new integrations — mid-acquisition by Adyen. |
| Sandbox | **E2B** (Firecracker) | You will run untrusted LLM-authored code for paying strangers next to your own API keys. Firecracker gives a separate kernel; gVisor does not. Daytona's 60 ms cold-start edge is not worth the blast radius. |
| Observability | **Langfuse** self-hosted | MIT, acquired by ClickHouse 2026-01-16 with licence and self-host intact. |
| Auth | **WorkOS** | Free to 1M MAU; SSO/SCIM become deal-blockers by your fifth enterprise conversation. Clerk's per-MAU pricing works against you exactly when you win. |
| Secret scanning | **Gitleaks** in-process + **TruffleHog** async | GitGuardian (Mar 2026): AI-assisted commits leak secrets at ~2× the human baseline. |
| Frontend | React 19 + **TanStack Query** + **shadcn/ui** + Tailwind + **AI Elements** | shadcn puts components in your repo — no abstraction layer for agents to fight. AI Elements already solves reasoning panels and tool-call rendering. **SSE, not WebSockets**, for agent output. |
| CI | SHA-pin every action; **merge queue with `merge_group` triggers** | `tj-actions/changed-files` (CVE-2025-30066) was compromised by *mutating tags* across 23,000+ repos. You are at 12/13 pinned — `actions/upload-artifact@v4` at `ci.yml:77` is the gap. |
| Releases | **release-plz + cargo-dist** | release-plz reasons from crates.io state rather than git tags — correct for Rust. |
